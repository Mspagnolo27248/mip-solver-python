Where the plan breaks

Products that overflow their tanks, run dry, or leave their control band inside the days shown. Overflow is the signal that a downgrade is needed.

Dashboards

Stream sheet

Every product in a stream, with its full daily balance — beginning inventory, production in, sales, forecast, blends, charged out, ending inventory and headroom. The same layout as the workbook tab.

Inventory projection

Daily balance for one product: begin, production in, demand out, charge out, ending inventory against tank capacity.

Charge schedule

What each unit charges, in barrels per day. Edit a cell and the projection re-simulates immediately.

Planned downtime

Days a unit cannot produce. Set these before running the optimizer — outside them every unit is expected to run. Click any Down cell in the grid below to toggle a single day.

Set a rate across the window

Writes one rate onto every day in the range. This is how a plan is laid down from scratch — set the crude, ROSE and Platformer rates for the whole window, then clear the units you want the optimizer to schedule for you. Days a unit is down are skipped. On MEK, extraction and ROSE, which run one feed at a time, a rate set on one line clears the unit's other lines on those days; on the Platformer, the hydrotreater and the transfers the other lines are left as they are.

Source data

Each value keeps what the source sent and what a planner changed it to. Re-syncing updates the source side only — your edits are never overwritten, and drift is flagged.

Upload source files

Load the small exports directly instead of re-importing the 6 MB planning workbook. Each file replaces its own feed; anything you have not uploaded keeps reading the workbook. A file whose columns have moved is rejected rather than half-imported, and your overrides survive as always. Uploading updates source data only — an open scenario keeps the numbers it was frozen with, so create a new one to plan on what you just loaded.

Optimizer inputs

The extra inputs automatic scheduling needs — prices, margins and solver settings. These are deliberately kept out of the planning side: a planner moving a charge by hand never needs them. Everything factual (yields, rates, capacities, feeds, downtime) comes from the planning side unchanged.

Runs & results

Each run solves the selected Current Plan and writes its answer back as an Optimized Result — a scenario that opens on the planning side like any other.

Model inputs

The yields, rates, capacities and control limits every projection rests on. Imported from the workbook and editable here — the imported value is always kept alongside your edit, so a re-import refreshes the source without discarding corrections.

New Current Plan

Freezes the source data as it is now - tank inventory, open orders and forecast - and starts from the charge schedule you pick. The plan date and the frozen data can't be changed once it is created.
